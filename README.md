# סקילים לעבודה עם AI

שני סקילים לאותו תהליך: מחדדים את המשימה, מאשרים הגדרה קצרה, מפיקים תוצר ומשפרים אותו בעזרת מבקר עצמאי.

| סקיל | שפת השיחה | מתאים ל־ |
| --- | --- | --- |
| [loophe](skills/loophe/SKILL.md) | עברית | תוכניות, החלטות, מחקרים ופיתוח |
| [loopen](skills/loopen/SKILL.md) | אנגלית | אותם שימושים באנגלית |

שפת התוצר יכולה להיות שונה משפת השיחה. מפעילים רק אחד מהם בכל משימה.

## מתחילים ממשימה אמיתית

אפשר להתחיל בתיאור קצר. מידע קיים וקבצים חוסכים שאלות:

> אני רוצה [תוצר], עבור [קהל/שימוש], כדי [ערך]. אלה המקורות והאילוצים: […]. הצלחה מבחינתי היא […].

ב־Claude Code, לדוגמה:

```text
/loophe הכן תוכנית קליטה של 30 יום למפתח חדש, לפי המסמך המצורף. התוצר מיועד לראש הצוות, וזמן החונכות הוא עד שעתיים ביום.

/loophe חקור שלוש חלופות לפתרון החיפוש באתר שלנו. אני צריך המלצה מנומקת, עם מקורות עדכניים ועלות משוערת שמסומנת כהערכה.

/loophe שפר את תהליך הוספת המוצר לסל במובייל לפי התקלה והצילומים המצורפים. בדוק את המימוש הקיים ואת הנחיות הפרויקט. המטרה היא שינוי קוד שניתן לבדוק מקומית.

/loopen Turn the attached product vision into a PRD with testable acceptance criteria. Keep technical implementation out of scope.
```

ב־Codex השתמשו באותן דוגמאות עם `$loophe` או `$loopen`.

## מה יקרה אחרי ההפעלה?

1. העוזר ייעזר בשיחה, בזיכרון ובהיסטוריה הזמינים כדי להציע הנחות וברירות מחדל, וישאל רק על פערים מהותיים. כשזה מועיל הוא יציע שאלות בחירה, ותמיד אפשר לענות גם באופן חופשי. כשהבקשה ברורה, הוא יציע מיד הגדרה.
2. תקבלו סיכום קצר של התוצר, המטרה, הגבולות ובדיקות ההצלחה ותאשרו אותו.
3. מבצע יכין תוצר ומבקר נפרד יבדוק אותו. ברירת המחדל היא עד 3 סבבים; אפשר להסכים על גבול אחר.
4. העבודה תסתיים ברגע שתעמוד בהגדרה, או בגבול שסוכם, עם תוצר וראיות בדיקה ומגבלות.

הסקילים מועילים כשיש תוצר ששווה לבקר ולשפר. שאלה קצרה או תיקון זעיר בדרך כלל אינם דורשים לולאה. ציונים אינם מדד מדעי לאיכות או הבטחה לתוצאה.

## התקנה

התקינו את **התיקייה השלמה** של כל סקיל, כולל `references`, `agents` ו־`assets`.

| סביבה | התקנה אישית | התקנה לפרויקט |
| --- | --- | --- |
| Claude Code | `~/.claude/skills/loophe/` ו־`loopen/` | `.claude/skills/loophe/` ו־`loopen/` |
| Codex | `~/.agents/skills/loophe/` ו־`loopen/` | `.agents/skills/loophe/` ו־`loopen/` |

הדרך הנוחה היא לבקש מהעוזר בסביבת העבודה:

```text
התקן את loophe ואת loopen מתוך https://github.com/heimanmorad/ai/tree/main/skills בתיקיית הסקילים האישית המתאימה לסביבה הזו. העתק כל תיקייה בשלמותה. אם קיימת גרסה ששונתה מקומית, הצג את ההבדלים לפני החלפתה. ודא ששני הסקילים מופיעים וזמינים להפעלה.
```

אפשר גם להוריד את המאגר מ־GitHub ולהעתיק את שתי התיקיות ידנית. ודאו שיש קובץ `SKILL.md` ישירות בכל תיקיית סקיל, בלי תיקיית סקיל נוספת בתוכה. אם הסקיל אינו מופיע, פתחו שיחה חדשה או הפעילו מחדש את הכלי.

בעדכון גרסה העתיקו שוב את כל תיקיית הסקיל, תוך שמירה על התאמות מקומיות. כל ריצה קיימת נשארת כפופה להגדרה שכבר אושרה בה.

התקנה מקומית מיועדת לסביבה המקומית. ב־ChatGPT Work או ב־Claude בדפדפן יש להשתמש במנגנון ההתקנה של המוצר. לולאה מלאה דורשת תתי־סוכנים אמיתיים והקשר נפרד למבקר; אם אין יכולת כזו, אפשר להשלים את ההגדרה ולהעביר אותה לסביבה תומכת.

ראו [תיעוד ההתקנה של Claude Code](https://code.claude.com/docs/en/skills) ו[תיעוד הסקילים של OpenAI](https://learn.chatgpt.com/docs/build-skills).

## שימוש ראשון בצוות

בחרו משימה מוגדרת שאתם מכירים. בדקו אם התוצר שימושי, כמה התערבות נדרשה ומה השתפר בעקבות הביקורת. התחילו ממשימה אחת לכל משתמש והרחיבו לפי התועלת בפועל.
